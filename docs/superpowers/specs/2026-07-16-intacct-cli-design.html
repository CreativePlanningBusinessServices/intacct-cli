1. Overview & goals

intacct-cli is a single-binary Rust CLI for AI agents (and humans) wrapping the modern Sage Intacct REST API (https://api.intacct.com/ia/api/v1, GA since Intacct 2025 R1). It is modeled closely on netsuite-cli: JSON-only stdout, structured JSON errors on stderr, deterministic exit codes, multi-account OAuth with OS-keyring secret storage, an embedded agent-facing skill, and self-update from GitHub releases.

Non-goals: the legacy XML API (explicitly out of scope; the session-id command exists only as Sage's documented escape hatch), per-object typed subcommands / OpenAPI codegen, table/human output formats, SOAP (Intacct has none).

Architecture decision (approved): generic commands over Intacct's platform endpoints. Objects are addressed by API path (accounts-payable/vendor), so all ~18 application groups, document-type objects (order-entry/document::Contract Invoice), and custom objects (platform-apps/nsp::my-object) work through one object command with zero per-object code. Schema discovery happens at runtime via the model service (describe). This mirrors netsuite-cli's generic record command and is immune to Sage's quarterly object additions. OpenAPI codegen was considered and rejected (spec is Cloudflare-gated, enormous generated surface, goes stale between releases, custom objects need the generic path anyway).

2. Crate layout

Mirrors netsuite-cli. main.rs is a 4-line #[tokio::main] shim calling intacct_cli::cli::cli_main(); all logic lives in the library so integration tests call command functions directly.

Every command handler returns Result<serde_json::Value, CliError>. Success → one JSON value on stdout, exit 0. Error → JSON error object on stderr, mapped exit code.

3. Command surface

Global flags: --account <alias> (fallback $INTACCT_ACCOUNT, then configured default) · --entity <id> (sets X-IA-API-Param-Entity, overrides the account's default entity) · --pretty. Clap config: color = Never, propagate_version, copy-paste-correct after_help examples on every subcommand.

4. Auth

Client-credentials (agent default)

POST /oauth2/token with grant_type=client_credentials, client_id, client_secret, username. Tenant selection is embedded in the username: userId@companyId, entity-scoped as userId@companyId|entityId. Prereqs (admin, once per company): a Web Services user, and the app's client ID authorized under Company → Security → Authorized Client Applications. Access token (~8–12h; expires_in is authoritative) cached in keyring with 60s leeway.

Auth-code + PKCE (interactive users)

Browser consent at GET /oauth2/authorize (response_type=code, S256 PKCE, state, scope=offline_access to obtain a refresh token). Redirect caught by a one-shot loopback HTTPS listener on 127.0.0.1:<port> (throwaway self-signed cert, 30s read / 300s overall timeouts, /callback only, no query-value echo) or --paste stdin fallback — ported from netsuite-cli. Intacct difference: refresh (grant_type=refresh_token) requires the client_secret — not a public client — so the secret is stored for auth-code accounts too. Rotated refresh tokens are persisted before first use, with netsuite-cli's rotation-failure handling (self-describing errors pointing at account add re-run).

Token plumbing

TokenProvider trait (object-safe, access_token() + invalidate()), CachedToken { access_token, expires_at_epoch } in keyring under <alias>#token. On HTTP 401 the client invalidates and retries once.

6. HTTP client & error model

IaClient: reqwest (rustls, no default features), base https://api.intacct.com/ia/api/v1 (env-overridable for wiremock), retry loop MAX_ATTEMPTS = 4, base backoff 500ms. 401 → invalidate + retry once; 429/5xx → honor Retry-After else exponential backoff. Success codes: 200/201/202/204/207. Successful bodies pass through unmodified (agents see documented ia::result/ia::meta shapes); 204 is synthesized into a small JSON acknowledgment.

7. Output conventions

  • stdout: exactly one JSON value per invocation; compact by default, --pretty to indent.
  • stderr: everything else — JSON error objects, prompts, browser URLs, warnings.
  • --all pagination merges pages into {items, count, totalCount, hasMore}, following ia::meta.next (query pages ≤4,000 rows), with a 1,000-page defensive cap and a misbehaving-server guard (stop if a page claims more but returns nothing).

8. Testing

  • Integration: wiremock per command family; tests call library command functions with an IaClient pointed at the mock server, StaticToken provider, and MemoryStore secrets. Failure-mode doubles (FailingSecretStore) prove write-ordering invariants.
  • Unit: inline #[cfg(test)] — PKCE vectors, username/tenant formatting, error-body mapping, pagination merging.
  • Live smoke: tests/live_smoke.rs, all #[ignore]d, gated on INTACCT_LIVE_ALIAS; becomes runnable once the Sage developer app is registered (we have a company; app registration is pending — mock-first is the plan).

9. CI, release & distribution

  • CI: macos/windows/ubuntu matrix running cargo test --locked; lint job with cargo fmt --check + clippy --all-targets -- -D warnings.
  • Release on v* tags: aarch64-apple-darwin, x86_64-apple-darwin, x86_64-pc-windows-msvc zips via softprops/action-gh-release.
  • update: self_update crate against CreativePlanningBusinessServices/intacct-cli (private → GITHUB_TOKEN); after swap, re-exec new binary's skill install.
  • .gitattributes enforces LF (embedded SKILL.md on Windows checkouts).

10. Agent skill

skills/intacct-cli/SKILL.md, embedded via include_str!. Contents: decision table (need → command), once-per-machine bootstrap, recipes (describe-before-writing; query paging with --all; batch + --atomic; bulk jobs for >500 records; entity scoping via --entity; idempotency keys on writes), exit-code → action table, gotchas (stdout is one JSON value; ia:: envelope shapes; account revoke kills all tokens for the user/company; 4,000-row query pages; 1 MB request bodies; username format carries the tenant).

11. Build order

  1. Foundations: error.rs, output.rs, config.rs, secrets.rs
  2. client.rs + client-credentials auth + context.rs
  3. account commands (add/list/set-default/remove/test)
  4. object CRUD + query + describe
  5. raw + auth-code/PKCE flow (loopback listener) + account revoke
  6. Services: job, composite, view, export, schedule, report, session-id
  7. skill + update + CI/release workflows

12. Reference material

  • Design reference: ~/projects/creativeplanning/netsuite-cli (module layout, auth plumbing, test patterns ported directly).
  • API docs: developer.sage.com/intacct/docs — Cloudflare-gated to plain fetches; key pages (OAuth2, query service, bulk, error handling, model service, owned objects, rate tiers) were captured during research and inform §3–§7.
  • OpenAPI reference: intacct-openapi (18 application groups; downloadable full spec exists but requires an interactive browser session — vendor manually if ever needed).
  • Rate behavior: monthly transaction tiers bill overage rather than block; concurrency breaches → 429/GW-0010. CLI honors 429 backoff and issues requests serially.
